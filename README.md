# AI Interferometry

迈克尔逊白光干涉实验智能辅助系统。程序通过 USB 相机采集干涉图像，使用 Ultralytics YOLO 识别条纹区域和类别，在检测区域内进一步定位中心条纹，并通过 RS-232 控制步进电机完成手动控制或自动寻零。另一台 USB 摄像头可拍摄数显微分表，由本地 PP-OCR 模型读取并向自动实验提供稳定读数。系统能够识别当前实验阶段，并在开启“自动进行实验”后自动寻找和记录白光中心条纹。实验辅助智能体用于解释当前进度、提示下一步、完成问答、误差计算和实验报告整理。

## 1. 主要功能

- USB 相机实时预览、分辨率设置和画面旋转、缩放、平移；
- YOLO 实时识别零级、近场和远场白光干涉条纹；
- 在 YOLO 检测区域周围自适应扩大二次搜索范围，计算中心条纹的像素位置；
- 对中心位置进行连续跟踪，记录参考位置和中心偏移；
- 连续分析画面中是否存在条纹，以及条纹向左、向右移动或基本稳定；
- 电机插件自动检测 CH340 等 USB 转串口，并保留正反转、停止、运行中换向、加减速和状态查询；
- 独立的电机自动寻中插件支持已搜索区间记忆、锁向扩展扫描、路标连续跟踪、可调快慢档、接近中心减速和稳定停车；
- 自动控制过程中执行超时、中心条纹丢失和串口异常保护；
- 使用独立摄像头、LCD 自动定位和 PP-OCRv6 ONNX 模型读取数显微分表，并进行连续帧稳定性确认；
- 自动识别人工调光、白光放置、设备初始化、中心搜索和完成等实验阶段；
- 提供独立的“自动进行实验”开关，关闭时不自动驱动电机；
- 录制原始画面或带识别结果的实验视频；
- 使用本地实验知识和 DeepSeek 提供实验辅助问答；
- 自动渲染助手输出中的标题、列表、表格、代码和常用公式。

## 2. 程序总体结构

程序采用分层结构。`run.py` 是启动入口，`src/ui/app.py` 是各模块的组装中心，但耗时的模型推理、串口通信和在线模型请求会放到后台执行，避免阻塞界面。

```text
用户与实验设备
      │
      ▼
┌─────────────────────────────────────────────┐
│ UI 层：src/ui                               │
│ 显示相机画面、插件面板、识别结果和运行状态   │
└───────────────────┬─────────────────────────┘
                    │
      ┌─────────────┼─────────────┐
      ▼             ▼             ▼
┌───────────┐ ┌───────────┐ ┌───────────────┐
│ 视觉模块   │ │ 控制与硬件 │ │ 实验辅助智能体 │
│ src/vision│ │ src/control│ │ src/agent     │
│ src/camera│ │ src/hardware│ └───────────────┘
└───────────┘ └───────────┘
      │             │             │
      └─────────────┴─────────────┘
                    │
                    ▼
        配置、日志、模型、知识库与实验数据
```

主要数据流如下：

```text
相机采集
  → 画面校正与 ROI 处理
  → YOLO 条纹识别
  → 中心条纹定位与跟踪
  → UI 显示、偏移记录或自动控制判断

用户问题 + 实验资料 + 当前实验状态
  → 实验辅助智能体
  → 预习、操作指导、误差计算或报告内容
```

## 4. 各目录与文件职责

### 4.1 根目录文件

| 文件 | 作用 |

| `config.yaml` | 相机、YOLO、串口、智能体、不确定度和窗口参数的统一配置。 |
| `config/video_demo.yaml` | 视频演示侧栏的双相机、YOLO、OCR 和自动寻中默认参数；文件内附中文注释。 |
| `pyproject.toml` | 定义 Python 版本、项目元数据和正式依赖范围。 |
| `requirements.txt` | 通过 `-e .` 安装当前项目，依赖版本仍以 `pyproject.toml` 为准。 |
| `README.md` | 项目完整说明文档。 |
| `ARCHITECTURE.md` | 记录系统分层、主要数据流、线程边界和安全约束。 |
| `PROJECT_STRUCTURE.md` | 较简洁的项目结构与开发约定。 |
| `快速使用.md` | 快速上手指南，适合初次使用。 |

### 4.2 `config/`：本机配置

- `calibration.yaml`：保存像素距离与物理量之间的标定信息；
- `secrets.yaml`：保存 DeepSeek API Key，由 `.gitignore` 排除，不会提交到 Git。

`config.yaml` 适合保存可以公开的运行参数，密钥等私密内容必须放在 `config/secrets.yaml` 或环境变量中。

### 4.3 `models/`：YOLO 模型

- `current/`：主程序启动时会按文件名排序，优先加载其中第一个 `.pt` 文件；
- `candidates/`：存放待比较或待切换的候选权重；
- `select.py`：交互式选择候选模型，并复制为 `current/model.pt`；
- 根目录中的其他 `.pt`：历史或备用模型，不会优先于 `current/`。

如果 `current/` 中没有模型，程序会回退到 `config.yaml` 的 `vision.model_path`。模型权重通常较大，已被 Git 忽略。

### 4.4 `resources/`：实验资料

- `agent_sources/`：保存下载到本地的实验指导书、技术资料及来源清单；

原始 PDF 用于资料核对和整理，不会直接作为聊天输出追加给用户。

### 4.5 `scripts/`：辅助脚本预留

此目录预留给开发辅助、构建和自动化脚本。当前为空，后续可按需添加。

### 4.6 `src/`：主程序源码

#### `src/agent/`：实验辅助智能体

| 文件或目录 | 作用 |
| --- | --- |
| `knowledge.py` | 加载、切分并按关键词检索本地 Markdown 知识。 |
| `provider.py` | 调用 OpenAI 兼容文本接口，目前用于 DeepSeek。 |
| `service.py` | 组织系统提示词、实验状态、检索结果、对话历史和离线降级回答。 |
| `session.py` | 在守护线程中执行助手请求，支持停止生成和安全退出。 |
| `knowledge_base/` | 整理后的实验原理、操作、故障诊断、不确定度和 AI 安全知识。 |

实验助手只读取实验状态，不直接向电机发送控制命令。

#### `src/camera/`：相机采集

- `manager.py`：负责扫描、打开和释放 USB 相机，设置分辨率与帧率，并读取 OpenCV 图像帧。

#### `src/control/`：自动控制逻辑

- `auto_control.py`：实现与 Tkinter、串口解耦的自动寻零状态机，根据视觉结果生成启动、调速或停止决策；
- `center_control.py`：根据中心条纹与画面中心的横向误差，生成正转、反转、分区调速和停车决策；
- `experiment_workflow.py`：识别整场实验进度，管理两项人工确认、设备初始化、自动搜索、中心稳定确认、结果记录和异常暂停。

#### `src/hardware/`：硬件通信

| 文件 | 作用 |
| --- | --- |
| `motor.py` | 实现 `R/r/S/D/+/-` 电机协议、JSON 状态解析、档位参数和内部自动调速。 |
| `micrometer.py` | 在后台线程读取第二摄像头，运行 LCD OCR，并发布稳定微分表读数。 |
| `command_queue.py` | 在单个后台线程中顺序执行串口任务，并让停止命令具有更高优先级。 |
| `arduino.py` | 读取 Arduino 发送的激光测距等辅助数据。 |

#### `src/vision/`：图像识别与中心定位

| 文件 | 作用 |
| --- | --- |
| `detector.py` | 封装 Ultralytics YOLO，负责模型加载、设备选择、ROI 推理和异常输入保护。 |
| `class_names.py` | 根据模型的类别名称映射零级条纹和彩色条纹语义，不依赖固定类别 ID。 |
| `roi.py` | 使用亮度、阈值和形态学方法定位干涉条纹有效区域。 |
| `angle.py` | 使用频域特征估计条纹倾斜角度。 |
| `correct.py` | 管理画面旋转校正、手动角度偏置、缩放和平移。 |
| `fringe_center.py` | 在白光竖条纹区域内估计中心位置，并通过 `CenterTracker` 平滑结果、短时保持和拒绝异常跳变。 |
| `fringe_motion.py` | 根据连续帧中的中心或非中心条纹位置，判断条纹存在性和水平移动方向。 |
| `micrometer_ocr.py` | 自动定位长条形 LCD，调用 PP-OCR 识别数字，并执行小数位恢复和多帧稳定化。 |

YOLO 检测框用于限定搜索范围，不直接把检测框中心当作最终中心条纹位置。

#### `src/ui/`：用户界面

- `app.py`：主界面控制器和唯一组装点，连接相机、视觉、电机、智能体与各插件；
- `theme.py`：统一颜色、字体和按钮样式；
- `markdown_renderer.py`：把助手输出中的 Markdown 和常见 LaTeX 表达渲染到 Tkinter 文本组件；
- `widgets/`：各功能面板，主界面通过组合这些面板构建网页式实验工作台。

自动寻中不会再根据非中心检测框变化立即掉头：程序优先锁定上一帧附近的
`near_fringe` 路标，使用多帧中值与移动方向记录趋势。线索只允许在刚启动时
选择一次首个搜索方向；本轮目标边界确定后，无论线索移动、抖动或短时消失，
电机都保持方向直到到达边界。只有识别到真正的中心条纹后，精确闭环才可以
根据中心误差提前改变方向。

中心条纹尚未识别时，无论画面中是否存在非中心线索，程序都会以启动位置为
虚拟零点，根据当前档位的标称转速估算
电机累计圈数，并采用交替扩展搜索：先检查 `0 → +R`，再快速穿过已检查区间
前往 `-R`，随后搜索 `+kR`、`-kR`，其中 `k` 为扩大倍数。已搜索区间只快速
通过，不再因为固定帧数重复掉头；视觉识别始终保持运行。左右最大范围都覆盖
后程序安全停车。初始范围、扩大倍数和最大范围可在自动寻中插件或
`config.yaml` 中调整；最大范围设为 `0` 时不设置范围上限，搜索半径会持续扩大。
每完成一轮左右边界覆盖，程序按“每轮加速档数”提高搜索速度，直到“最快搜索
档位”，已搜索区间的返回速度也同步提高。默认仍保留 600 秒运行超时、串口失联
停车和人工停止。这里的圈数来自运行时间和标称转速积分，不是编码器实测值。
搜索范围在非中心线索引导、中心条纹接近、反向微调、稳定确认和最终停车阶段都会
持续输出；找到中心后界面显示最终累计范围和停车位置，不再显示尚未到达的旧边界。
中心候选必须连续出现3帧才会被记为“曾找到中心”，单帧误识别消失后直接继续
范围搜索。已经确认的中心丢失时，程序先停车等待；`near_fringe` 重新出现便立即
恢复，持续90个推理帧仍未恢复则重新进入扩展搜索，而不是结束自动任务。

## 6. 配置说明

### 6.1 主配置 `config.yaml`

主要配置项包括：

- `camera`：相机索引、分辨率和帧率；
- `vision`：模型路径、置信度、IoU、输入尺寸和运行设备；
- `motor`：电机串口自动检测、波特率、超时、自动寻中参数和安全限制；
- `micrometer`：第二摄像头索引、OCR 模型路径、分辨率、ROI、置信度、固定小数位、多帧稳定参数、突变阈值、异常确认帧数和机构放缩系数；
- `experiment`：自动实验最大时间、中心稳定帧数、置信度和最大位置抖动；
- `arduino`：Arduino 串口参数；
- `agent`：DeepSeek 接口地址、模型、超时、输出长度和检索数量；
- `uncertainty`：置信水平等误差分析参数；
- `ui`：主题、语言和窗口大小。

微分表 OCR 建立首个稳定值后会持续发布该可信值，不会因单帧无效或候选未稳定而闪回空值。仪表的 `-.002` 按三位小数解释为 `-0.002 mm`，主读数也按三位小数显示。相邻变化超过 `max_step_mm` 时需要 `jump_required` 个连续一致帧才能更新；只有比例接近 `×10/÷10` 且绝对变化同时超过突变阈值，才视为小数点或位数误识别并保持旧值，避免把靠近零点的正常变化误判。界面、临时测量、回程差测量、日志和实验助手共用同一可信读数，同时保留最后一次真实确认时间；显示可以保持，过期值不能继续驱动电机。

如果配置使用 CUDA，但当前 PyTorch 无法使用 CUDA，YOLO 会记录警告并回退到 CPU。

### 6.2 视频演示预设 `config/video_demo.yaml`

手动页默认使用视频演示精简侧栏，只保留以下核心操作：

1. 启动第一相机，在右侧主画布显示干涉条纹；
2. 启动第二相机，在左侧栏显示微分表读数画面和稳定读数；
3. 记录当前中心条纹位置；
4. 加载 YOLO 模型；
5. 开始预测并自动检测中心条纹；
6. 勾选“沿同一方向旋转”后自动寻找条纹并寻中，或随时停止。

相机画面、YOLO 阈值与 ROI、电机、自动寻中和测量等完整设置统一放在侧栏底部的“高级参数与完整控制”模块中，该模块及其内部面板默认折叠。

录制前可直接编辑 `config/video_demo.yaml`。修改后重启程序即可应用，无需在拍摄现场临时打开高级面板。主要分组如下：

| 分组 | 参数作用 |
| --- | --- |
| `main_camera` | 第一相机索引、分辨率、帧率、画面旋转、缩放、运动曝光和增益。 |
| `reading_camera` | 第二相机索引、分辨率、帧率、OCR 间隔、ROI、置信度和稳定读数帧数。 |
| `yolo` | YOLO 置信度、IoU、推理尺寸以及开始预测后是否自动检测中心条纹。 |
| `auto_center` | 同方向旋转默认状态、旋转方向、搜索档位、中心容差、稳定帧数和搜索范围。 |

该文件只覆盖视频演示界面的启动默认值；模型路径、串口安全限制、智能体和其他全局配置仍由 `config.yaml` 管理。文件中的每个参数均附有中文注释和单位说明。

### 6.3 DeepSeek 密钥

在本机文件 `config/secrets.yaml` 中填写：

```yaml
# 仅保存在本机，不会提交到 Git
deepseek_api_key: "你的 DeepSeek API Key"
```

也可以在启动程序前设置环境变量；环境变量优先级更高：

```powershell
$env:DEEPSEEK_API_KEY="你的 DeepSeek API Key"
python run.py
```

未配置密钥时，助手会使用本地知识检索结果进行降级回答。在线模式使用 `deepseek-v4-pro`。助手保留最近 12 轮长对话，并随问题附加两路摄像头、画面矫正与 ROI、YOLO 逐目标结果、中心条纹、电机、微分表 OCR、测量记录和最近 100 条结构化日志。实验助手以页面内浮窗显示，可拖动标题栏移动、拖动右下角改变尺寸，或使用“－ / ＋ / 收回”按钮调整显示；第四模块中的“打开助手”按钮可随时恢复浮窗。可以在浮窗中使用“测试连接”检查 DeepSeek 状态。

临时测量作为独立的第五模块：当前读数低于目标时正转以增大读数，高于目标时反转以减小读数，进入容差后立即停车。有效 OCR 读数暂时丢失时不会猜测方向，而是停车等待新读数；旧的排队旋转命令在方向变化或停止后自动失效。

第五模块的回程差测量采用单向越过式端点控制。起点读数必须小于终点读数；到达端点附近（默认 `±0.01 mm`）或沿当前方向越过端点即进入下一阶段，不会为了精确落在起点或终点而反复正反转。正式去程保持正转，终点只进行一次必要换向，回程保持反转，从而避免端点修正本身引入额外回程差。

是否显示第五模块由 `config.yaml` 中的 `temporary_measurement.enabled` 控制：设为 `true` 时显示模块及导航入口，设为 `false` 时两者同时隐藏，修改后重启程序生效。

助手的下一步动作严格按以下流程判断：

1. 调整仪器，放置白光光源；
2. 打开两个摄像头，连接电机；
3. 矫正预览画面，标注 ROI；
4. 加载模型，开始预测，开始自动分析条纹；
5. 开始自动寻中。

### 6.4 标定配置

标定信息保存在 `config/calibration.yaml`。中心条纹模块首先输出像素坐标和像素偏移；需要换算为真实距离时，应使用与当前相机位置、分辨率和光路条件相匹配的标定数据。

### 6.5 电机串口协议

电机控制插件只提供手动控制。连接串口后，界面按照下表发送单字符命令：

| 命令 | 功能 |
| --- | --- |
| `R` | 正转启动 |
| `r` | 反转启动 |
| `S` | 停止 |
| `D` | 电机运行时切换方向 |
| `+` | 加速一个档位 |
| `-` | 减速一个档位 |
| 其他字符 | 请求电机返回 JSON 状态；程序默认发送 `?` |

固件的 10 档速度参数如下，档位数字越小，转速越高：

| 档位 | 脉冲频率（Hz） | 角速度（deg/s） | 每转耗时（s） |
| ---: | ---: | ---: | ---: |
| 1 | 5000 | 1125 | 0.32 |
| 2 | 4450 | 1001 | 0.36 |
| 3 | 3900 | 877 | 0.41 |
| 4 | 3350 | 754 | 0.48 |
| 5 | 2800 | 630 | 0.57 |
| 6 | 2250 | 506 | 0.71 |
| 7 | 1700 | 382 | 0.94 |
| 8 | 1150 | 259 | 1.39 |
| 9 | 800 | 180 | 2.00 |
| 10 | 500 | 112 | 3.20 |

自动寻中使用同一套底层命令。可在“电机自动寻中”插件中调整搜索档位、快速档位、接近档位、减速距离、中心容差和首次探测方向；默认值保存在 `config.yaml` 的 `motor.automatic` 中。

自动寻中默认将画面水平中心作为目标。在中心条纹出现前，程序先对 `near_fringe` 线索进行多帧确认；稳定线索会决定电机方向，并把虚拟搜索区间的中心向线索方向平移。电机先到达新的搜索中心，再从该中心向两边交替扩大；已覆盖区间仍会被记录，返回时快速穿过，避免重复搜索和中途来回换向。持续线索每完成一轮扩张最多修正一次搜索中心，单帧误检和检测框抖动不会不断拖动搜索区间。相关阈值保存在 `motor.automatic.guide_focus_*` 配置中。

识别中心条纹后，两种搜索方案共用原有移动方法：程序慢速探测并根据条纹横坐标变化学习“正转使条纹向左或向右”，随后进入允许按中心误差换向的精确闭环。已知方向单向方案只限定中心条纹出现前的搜索方向；找到后不再执行搜索，只有确认条纹丢失后才恢复沿已知方向搜索。中心条纹距离目标较远时使用快速档位，进入减速距离后使用接近档位；进入中心容差后立即停车，并在连续稳定达到设定帧数后确认完成。

## 7. 智能实验流程使用方法

人工必须完成的操作只有两项：

1. 使用红光调整仪器，使干涉条纹清晰且接近零光程差；
2. 放置白光光源。

程序顶部提供“手动操作”和“自动实验”两个独立页面。微分表摄像头索引、ROI 和录像路径等参数仍可先在手动页设置；自动实验开始后，程序会自动尝试启动主相机、YOLO、实时预测、电机和微分表读数。微分表与主相机索引冲突时会自动选择另一台空闲摄像头。

默认使用摄像头索引 `1` 作为干涉条纹主相机，索引 `0` 作为微分表读数相机。主相机由后台采集线程持续保存最新帧，自动页实时预览与 YOLO 推理分别读取该最新帧，因此推理速度不会再阻塞相机画面刷新。

完成后切换到“自动实验”页面，在“智能实验流程”面板依次勾选“仪器已用红光调整完成”和“白光光源已放置完成”，再打开“自动进行实验”。完整自动流程最长运行 `600` 秒（10分钟）。自动页同时显示干涉条纹和微分表两路实时画面，以及阶段进度、运行时间、设备连接、中心坐标、目标误差、置信度、条纹移动、搜索状态、参考读数、当前读数和动镜位移。默认自动录制干涉画面，也可以关闭该选项；“紧急停车”会立即关闭自动流程、停止电机并结束自动录像。

自动页的“设备调试”区域可直接选择干涉相机索引、微分表相机索引和电机串口，并连接或关闭设备、加载或停止模型。画面控制与手动页使用同一个 `FrameCorrector` 和 ROI 状态：默认可选 `2.0` 倍缩放，可输入旋转角度；开启“画 ROI”后在左侧干涉预览拖拽框选，开启“拖拽移动画面”后可直接拖动画面，也可使用方向按钮微调和一键复位。ROI 与移动模式互斥，避免一次拖拽同时改变两种状态。

“自动寻找中心条纹”同时保留在手动操作页和自动实验页，两个入口共享同一套电机寻中状态及参数。搜索时电机保持连续旋转；默认不再随搜索范围扩大逐轮加速。若连续多帧看不清条纹，程序只会降至较慢档位恢复清晰度，不会采用转停交替方式。

自动寻中面板默认开启“始终显示画面中心线”。只要主相机有实时画面，无论自动寻中、电机或模型是否运行，手动页与自动实验页都会在画面中央显示贯穿完整画面的青色参考线；该参考线只属于界面叠加层，不会进入 YOLO 输入或中心条纹定位计算。

为降低连续旋转造成的运动模糊，默认搜索使用档位 `9`，接近中心或连续漏检时使用档位 `10`。主相机在自动寻中开始时从普通预览参数切换到运动清晰度增强参数，并根据中心区域的拉普拉斯清晰度、亮度和寻中前基线自动调整曝光与增益。运动期间的软件增强会沿竖直方向平均噪声、通过水平带通分离低对比度周期条纹、放大白光条纹的弱色差，再恢复水平拖影边缘；增强结果同时用于实时预览和 YOLO 识别，且不改变画面尺寸与坐标。停止寻中后恢复原始画面。两个自动寻中面板会实时显示清晰度、基线、曝光、增益以及锐化、条纹和色彩增强倍数。

“摄像头与画面控制”的清晰度配置也可手动开启运动增强。该开关默认关闭，默认曝光为 `-7.0`、增益为 `80.0`；修改参数后无需重开摄像头。自动寻中会临时请求运动增强，停止后恢复手动开关原有状态。

程序随后驱动电机寻找白光中心条纹，并在中心位置连续稳定后停车和保存记录。视觉微分表已获得稳定读数时，流程会自动记录参考读数和停车后的中心读数；读数尚未稳定时保持停车等待，不会把旧 OCR 值写入实验结果。没有可用微分表摄像头时会提示失败，但仍允许仅完成中心条纹寻中。

面板始终显示当前阶段、下一步和完成进度。关闭自动实验开关会立即结束自动搜索，但不会影响实验助手的普通问答功能。

配置中的 `scale_factor` 用于表示机构放缩系数：

```text
动镜实际位移 = (当前千分尺读数 - 参考读数) × scale_factor
```

如果仪器传动比为 `1/20`，可以设置 `scale_factor: 0.05`；应以实际机械结构或标定结果为准。

## 8. YOLO 模型要求

模型类别名称必须能够表达条纹语义。当前程序通过名称关键词进行兼容映射，例如：

- `zero_order`、包含 `zero` 或 `order` 的类别映射为零级条纹角色；
- `near_fringe`、`far_fringe`、包含 `color` 或 `fringe` 的类别映射为彩色条纹角色。

程序不会假设类别 ID 永远固定，因此更换模型时应检查模型的 `model.names`，不要只检查类别编号。

## 10. 安全注意事项

- 首次联调应让电机空载，并使用低速、小范围运动；
- 自动控制前必须确认串口协议、运动方向和停止命令正确；
- 自动控制中的超时和条纹丢失停止不能替代机械限位；
- 模型、相机或电机插件关闭时，应同步停止预测和自动控制；
- 实验助手没有硬件控制权限，硬件动作由确定性程序和状态机处理；
- 关闭程序前应确认电机已经停止。

## 11. 开发约定

- 不要在 Tkinter 回调中直接执行模型推理、串口等待或在线请求；
- 新的自动控制逻辑优先放入 `src/control/`，并补充无硬件测试；
- YOLO 类别判断必须读取类别名称，不依赖固定类别 ID；
- 密钥、模型权重、原始 PDF、日志和临时数据不提交到 Git；
- 依赖版本统一维护在 `pyproject.toml`；
- 新增界面功能优先写成 `src/ui/widgets/` 下的独立插件；
- 可确定计算结果的误差和报告逻辑应逐步从大模型回答中拆出，放入 `src/uncertainty/` 和 `src/report/`。

更详细的线程边界和模块调用关系见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。
