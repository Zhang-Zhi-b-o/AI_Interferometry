# AI Interferometry

迈克尔逊白光干涉实验智能辅助系统。程序使用 USB 相机采集干涉图像，通过双类别
YOLOv8 模型识别零级条纹和近场条纹，在检测框内进一步定位中心条纹，并通过
RS-232 控制步进电机完成自动搜索和闭环寻中。第二台相机可读取数显微分表，系统还
提供视频录制、临时位移控制、回程差测量和实验辅助问答。

## 当前版本

- 主分支：`main`
- 当前模型：`models/current/best.pt`（`yolov8n_all_human_confirmed`，来源和历史见
  `models/MODEL_SOURCES.md`）
- 模型类别：`0 = zero_order`，`1 = near_fringe`
- 默认推理：`imgsz=640`、候选 `conf=0.25`、模型 NMS `iou=0.70`、优先 CUDA
- 默认自动寻中：已知方向单向搜索，搜索档位 9，模糊安全档位 10
- Python：3.10 或更高版本

当前模型由合并后的全部人工确认数据训练，最佳权重位于第 110 轮，验证结果如下：

| Precision | Recall | mAP50 | mAP50-95 |
| ---: | ---: | ---: | ---: |
| 0.896 | 0.910 | 0.951 | 0.774 |

验证集的最佳综合 F1 约为 `0.91`，对应置信度约 `0.50`。上一版
`pre_annotation_yolov8n_pool_after_1240_best` 已归档到 `models/history/`。

### 统一检测筛选策略

模型以 `0.25` 输出候选，再由 `src/vision/detection_strategy.py` 统一筛选。实时画框、
中心定位、近场路标、时序融合和自动寻中全部使用筛选结果。

- `≥0.60` 为高可靠框；`0.50～0.60` 接受并标记复核；`0.30～0.50` 只有与最近
  两帧中的同类可靠框匹配才保留。实时模式只使用已经到达的历史帧，不凭空补框；
- 取消旧模型的固定中心与固定宽高范围，只删除越界、非有限值、边长小于图像
  `0.015` 或面积小于整图 `0.003` 的明显非法框，因此允许多视场和接近全图的大框；
- 同类框按置信度排序，IoU `≥0.65` 或小框覆盖率 `≥0.80` 时只保留最高置信度者；
  `zero_order` 最多 2 个，`near_fringe` 最多 4 个；
- 跨类别 IoU `<0.75` 时都保留；达到 `0.75` 后，仅在置信度差至少 `0.15` 时删除
  较低者，否则都保留并标记复核；
- 两个黑框、3～4 个彩框、时序挽救、跨类别高度重合、超出数量上限，以及空结果中
  存在未确认弱框时，策略结果都会携带 `needs_review` 和具体原因。

这套阈值保持 `0.50` 的常规精度，同时用 `0.30` 的时序挽救下限减轻运动模糊和偶发
漏检，偏向保证条纹能连续识别；弱框不会无限续接，只能由最近可靠帧提供依据。

## 主要功能

- 干涉相机实时预览、旋转、缩放、平移、ROI 和视频录制；
- YOLO 实时检测 `zero_order` 与 `near_fringe`；
- 在零级检测框的扩展区域内定位实际中心条纹，不把框中心直接作为结果；
- YOLO 短时漏检时，在上一帧区域内继续视觉跟踪中心；
- 识别倾斜、弯曲、变色和低对比度条纹，使用历史轨迹跨越短时漏检；
- 根据连续位置估计条纹移动方向、位移和速度；
- 针对电机运动模糊自动降低速度，清晰画面恢复后再恢复正常控制；
- 搜索方向与识别节拍独立选择，可组成四种自动寻中方式；
- 使用第二台相机和本地 PP-OCRv6 ONNX 模型读取数显微分表；
- 支持目标读数控制、回程差测量、原始/标注视频录制；
- 使用本地知识库和 DeepSeek 提供实验操作、计算与报告辅助；
- 提供单张彩色干涉图的相对厚度分布分析工具。

## 自动寻找中心条纹

自动寻中的目标是把识别到的零级中心条纹移动到画面水平中心。YOLO 负责提供零级框
和近场路标，局部图像算法负责框内精确定位，时序跟踪负责平滑位置并处理短时漏检。

### 两组必选策略

界面将原来的三个互斥选项拆成两个独立选项组，每组必须选择一项：

1. **搜索方向**
   - 未知方向，双向寻找：以启动位置为虚拟零点，记录已搜索范围并交替扩展左右区域；
   - 已知方向，单向寻找：中心出现前始终沿人工选择的正转或反转方向搜索。

2. **识别方式**
   - 边转边识别（默认）：电机连续旋转，视觉系统持续识别并处理运动模糊；
   - 转一段，停下识别：定时转动、停车、等待画面稳定，再连续检查若干帧。

两组可自由组合，例如“未知方向 + 转停识别”会在双向扩展范围内分段转停，
“已知方向 + 转停识别”则始终沿指定方向分段搜索。转停方式只在停车稳定阶段接受中心
候选，避免运动模糊误判；中心候选确认期间保持停车。任何组合找到中心后都复用同一套
标准闭环完成居中。

双向方式会快速穿过已检查区域，连续可靠的 `near_fringe` 路标可平移搜索中心；
检测框抖动或单帧误检不会触发频繁换向。单向方式中的历史信息只用于保持方向和模糊
降速，确认中心后才允许为闭环居中而换向。

### 模糊、漏检与历史信息

视觉融合不只依赖单帧 YOLO。程序会分析二维局部纹理，以补偿条纹倾斜、弯曲、颜色
变化和模型偶发漏检；位置历史用于估计速度，并在短时运动模糊期间预测条纹位置。
历史预测不能单独触发换向或迁移搜索中心，只能保持运动连续并降低速度。

连续模糊或完全没有视觉证据达到设定帧数后，控制器进入安全慢速状态；连续获得清晰
证据后才退出。为了降低实时负载，YOLO 正常命中时默认每 3 帧更新一次纹理分析；
YOLO 漏检时仍逐帧分析，不降低补漏能力。

中心候选需要连续多帧确认。进入中心容差后电机立即停止，连续稳定达到设定帧数后才
判定完成。中心短时丢失会先保持或等待，持续丢失后才恢复搜索。自动控制同时具有最长
运行时间、串口失联和人工停止保护；这些软件保护不能替代机械限位。

## 界面模块

主界面由五个可折叠模块组成：

| 模块 | 内容 |
| --- | --- |
| 01 视觉观察 | 相机、模型预测、中心条纹、ROI、实时状态和录像 |
| 02 运动控制 | 电机连接、手动命令及方向策略 × 识别方式的自动寻中组合 |
| 03 测量记录 | 微分表相机、OCR、稳定读数和时间戳 |
| 04 实验助手 | 本地知识/DeepSeek 问答和运行日志 |
| 05 临时测量 | 目标读数控制与回程差测量，可通过配置隐藏 |

视频演示侧栏提供启动双相机、记录位置、加载模型、开始预测和按已知方向寻中的快捷
入口。自动寻中面板默认折叠档位、容差、范围、模糊和转停节拍等参数，仅保留两组模式
选择、方向、启动按钮和状态；需要时展开“参数调整”。画面中心参考线只属于 UI 叠加层，不会进入
YOLO 输入、录像原始帧或中心定位计算。

## 安装与启动

在 PowerShell 中执行：

```powershell
cd D:\Files\Work\光电\AI_Interferometry
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python run.py
```

如果 PowerShell 禁止激活脚本，可先仅对当前终端放开：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\.venv\Scripts\Activate.ps1
```

CUDA 不可用时，YOLO 会记录警告并自动回退到 CPU。

## 推荐操作顺序

1. 调整光路并放置白光光源；
2. 启动干涉相机，确认旋转、缩放和 ROI；
3. 加载 `models/current/best.pt` 并开始预测；
4. 连接电机，先用手动命令确认物理方向和停止命令；
5. 根据实验状态选择单向、双向或转停识别模式；
6. 低速、小范围试运行后再开始正式自动寻中；
7. 需要读数时启动第二相机和微分表 OCR；
8. 完成后停止电机、预测、录像并关闭相机。

## 配置

### `config/video_demo.yaml`

这是当前视频演示和自动寻中的唯一默认参数来源，修改后需要重启程序。

| 分组 | 主要内容 |
| --- | --- |
| `main_camera` | 干涉相机索引、分辨率、帧率、角度、缩放和清晰度增强 |
| `reading_camera` | 微分表相机、OCR 模型、ROI、稳定窗口和读数校验 |
| `yolo` | 当前模型、设备、阈值、中心搜索、纹理分析和历史跟踪 |
| `motor` | 串口、波特率、超时和安全限制 |
| `auto_center` | 方向策略、识别方式、档位、容差、模糊恢复和搜索范围 |

缺少必填项、类型错误或模型文件不存在时，程序会在启动阶段明确报错，不会静默使用
另一套默认值。

关键参数：

- `yolo.fringe_texture_interval_frames`：YOLO 命中时的纹理分析间隔；
- `yolo.confidence_threshold` 与 `yolo.iou_threshold`：统一策略固定的候选阈值
  `0.25` 和模型 NMS 阈值 `0.70`；
- `auto_center.direction_mode`：`single_direction` 或 `bidirectional`；
- `auto_center.recognition_mode`：`continuous` 或 `stop_and_detect`；
- `auto_center.blur_slowdown_frames`：连续模糊/无证据多少帧后降速；
- `auto_center.blur_safe_gear`：模糊期间使用的安全档位；
- `auto_center.stop_detect_move_seconds`：转停模式每轮转动时间；
- `auto_center.stop_detect_settle_seconds`：停车后的画面稳定等待时间；
- `auto_center.stop_detect_frames`：停车后连续检测帧数。

### `config.yaml`

保存实验助手、临时测量、Arduino、不确定度和窗口参数。密钥不要写入该文件。

DeepSeek 密钥保存到不会提交 Git 的 `config/secrets.yaml`：

```yaml
deepseek_api_key: "你的 DeepSeek API Key"
```

也可以使用环境变量：

```powershell
$env:DEEPSEEK_API_KEY="你的 DeepSeek API Key"
python run.py
```

未配置密钥时，实验助手使用本地知识库降级回答。助手只读取状态，不直接控制硬件。

## 电机协议

程序使用单字符串口命令：

| 命令 | 功能 |
| --- | --- |
| `R` | 正转启动 |
| `r` | 反转启动 |
| `S` | 停止 |
| `D` | 运行中换向 |
| `+` | 加速一档 |
| `-` | 减速一档 |
| `?` | 查询状态 |

档位 1 最快、档位 10 最慢。自动寻中复用相同底层协议，并将串口任务放入后台队列，
避免阻塞 Tkinter 界面。

核心视觉数据流：

```text
相机帧
  → 旋转、缩放和运动清晰度增强
  → YOLO 双类别检测
  → 零级框内中心定位 / 近场路标
  → 二维纹理补检 + 历史位置与速度融合
  → 自动寻中状态机
  → 后台串口命令队列
```

## 微分表与临时测量

微分表模块使用独立相机自动定位 LCD，并通过多帧确认、小数位恢复、突变校验和读数
时间戳提供可信数值。暂时识别失败时可保持上一个显示值，但过期值不会继续驱动电机。

临时测量默认约定正转使读数增大、反转使读数减小。没有新鲜可信读数时立即停车等待，
不会猜测方向。回程差测量按单向越过端点的方式执行，避免端点附近反复换向引入额外
回程差。

## 厚度分布分析

`Thickness_variation_analysis/` 可从单张彩色干涉图生成相对厚度云图、叠加图、截面
曲线、置信度图、CSV 和 HTML/Markdown 报告：

```powershell
python Thickness_variation_analysis/analyze.py image.jpg `
  -o Thickness_variation_analysis/output `
  --refractive-index 1.523 --wavelength-nm 589.3
```

没有无薄膜基准和颜色—光程差标定时，结果是模型依赖的相对厚度估计，不应作为可溯源
的绝对厚度。完整说明见
[`Thickness_variation_analysis/README.md`](Thickness_variation_analysis/README.md)。

## 安全与开发约定

- 首次电机联调必须空载、低速、小范围进行；
- 确认物理方向和 `S` 停止命令后再启用自动寻中；
- 软件超时和漏检保护不能替代机械限位；
- 不在 Tkinter 回调中执行推理、串口等待或在线请求；
- YOLO 类别判断必须依据类别名称，不依赖固定类别 ID；
- 新控制逻辑应放入 `src/control/` 并补充无硬件测试；
- API 密钥、日志、临时数据和未经筛选的大型实验材料不提交 Git。
