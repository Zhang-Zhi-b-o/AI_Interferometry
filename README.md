# AI Interferometry

迈克尔逊白光干涉实验智能辅助系统。程序通过 USB 相机采集干涉图像，使用 Ultralytics YOLO 识别条纹区域和类别，在检测区域内进一步定位中心条纹，并通过 RS-232 控制步进电机完成手动控制或自动寻零。系统能够识别当前实验阶段，并在开启“自动进行实验”后自动寻找和记录白光中心条纹。实验辅助智能体用于解释当前进度、提示下一步、完成问答、误差计算和实验报告整理。千分尺读数接口暂时预留，待硬件方案确定后接入。

## 1. 主要功能

- USB 相机实时预览、分辨率设置和画面旋转、缩放、平移；
- YOLO 实时识别零级、近场和远场白光干涉条纹；
- 在 YOLO 检测区域内计算中心条纹的像素位置；
- 对中心位置进行连续跟踪，记录参考位置和中心偏移；
- 电机插件只保留串口连接、正反转、停止、运行中换向、加减速和状态查询；
- 自动控制过程中执行超时、条纹丢失和串口异常保护；
- 预留千分尺读数和动镜位移换算接口，具体读取方式待确定；
- 自动识别人工调光、白光放置、设备初始化、中心搜索和完成等实验阶段；
- 提供独立的“自动进行实验”开关，关闭时不自动驱动电机；
- 录制原始画面或带识别结果的实验视频；
- 使用本地实验知识和 DeepSeek 提供实验辅助问答；
- 自动渲染助手输出中的标题、列表、表格、代码和常用公式。

## 2. 程序总体结构

程序采用分层结构。`run.py` 是启动入口，`src/ui/app.py` 是各模块的组装中心，但耗时的模型推理、串口通信和在线模型请求会放到后台执行，避免阻塞界面。

```text
用户与实验设备
      │
      ▼
┌─────────────────────────────────────────────┐
│ UI 层：src/ui                               │
│ 显示相机画面、插件面板、识别结果和运行状态   │
└───────────────────┬─────────────────────────┘
                    │
      ┌─────────────┼─────────────┐
      ▼             ▼             ▼
┌───────────┐ ┌───────────┐ ┌───────────────┐
│ 视觉模块   │ │ 控制与硬件 │ │ 实验辅助智能体 │
│ src/vision│ │ src/control│ │ src/agent     │
│ src/camera│ │ src/hardware│ └───────────────┘
└───────────┘ └───────────┘
      │             │             │
      └─────────────┴─────────────┘
                    │
                    ▼
        配置、日志、模型、知识库与实验数据
```

主要数据流如下：

```text
相机采集
  → 画面校正与 ROI 处理
  → YOLO 条纹识别
  → 中心条纹定位与跟踪
  → UI 显示、偏移记录或自动控制判断

用户问题 + 实验资料 + 当前实验状态
  → 实验辅助智能体
  → 预习、操作指导、误差计算或报告内容
```

## 4. 各目录与文件职责

### 4.1 根目录文件

| 文件 | 作用 |
| --- | --- |
| `run.py` | 程序入口。加载配置和日志后调用 `src.ui.run_app()` 启动界面。 |
| `config.yaml` | 相机、YOLO、串口、智能体、不确定度和窗口参数的统一配置。 |
| `pyproject.toml` | 定义 Python 版本、项目元数据和正式依赖范围。 |
| `requirements.txt` | 通过 `-e .` 安装当前项目，依赖版本仍以 `pyproject.toml` 为准。 |
| `capture.py` | 监听 Windows 键盘输入，用于判断测量设备是否以 HID 键盘形式输出数据。 |
| `capture_micrometer.py` | 尝试从串口和标准输入捕获数显微分头数据，属于设备探查脚本，不是主程序入口。 |
| `ARCHITECTURE.md` | 记录系统分层、主要数据流、线程边界和安全约束。 |
| `PROJECT_STRUCTURE.md` | 较简洁的项目结构与开发约定。 |

### 4.2 `config/`：本机配置

- `calibration.yaml`：保存像素距离与物理量之间的标定信息；
- `secrets.yaml`：保存 DeepSeek API Key，由 `.gitignore` 排除，不会提交到 Git。

`config.yaml` 适合保存可以公开的运行参数，密钥等私密内容必须放在 `config/secrets.yaml` 或环境变量中。

### 4.3 `models/`：YOLO 模型

- `current/`：主程序启动时会按文件名排序，优先加载其中第一个 `.pt` 文件；
- `candidates/`：存放待比较或待切换的候选权重；
- `select.py`：交互式选择候选模型，并复制为 `current/model.pt`；
- 根目录中的其他 `.pt`：历史或备用模型，不会优先于 `current/`。

如果 `current/` 中没有模型，程序会回退到 `config.yaml` 的 `vision.model_path`。模型权重通常较大，已被 Git 忽略。

### 4.4 `resources/`：实验资料和静态资源

- `agent_sources/`：保存下载到本地的实验指导书、技术资料及来源清单；
- `agent_sources/README.md`：说明资料来源、用途和整理结论；
- `icons/`：为界面图标预留；
- `samples/`：为离线测试图像、视频或演示素材预留。

原始 PDF 用于资料核对和整理，不会直接作为聊天输出追加给用户。

### 4.5 `scripts/`：设备探查脚本

这里存放不参与主程序启动的独立工具：

- `ble_scan.py` 使用 `bleak` 扫描 BLE 设备并查看 GATT 服务；
- `ble_scan_qlr.py` 使用 Windows Runtime 深入读取指定青量测微器的 BLE 特征。

这两个脚本属于硬件研究工具，可能需要额外安装 `bleak` 或 `winrt` 相关依赖；主程序的依赖不包含这些可选包。

### 4.6 `src/`：主程序源码

#### `src/agent/`：实验辅助智能体

| 文件或目录 | 作用 |
| --- | --- |
| `knowledge.py` | 加载、切分并按关键词检索本地 Markdown 知识。 |
| `provider.py` | 调用 OpenAI 兼容文本接口，目前用于 DeepSeek。 |
| `service.py` | 组织系统提示词、实验状态、检索结果、对话历史和离线降级回答。 |
| `session.py` | 在守护线程中执行助手请求，支持停止生成和安全退出。 |
| `knowledge_base/` | 整理后的实验原理、操作、故障诊断、不确定度和 AI 安全知识。 |

实验助手只读取实验状态，不直接向电机发送控制命令。

#### `src/camera/`：相机采集

- `manager.py`：负责扫描、打开和释放 USB 相机，设置分辨率与帧率，并读取 OpenCV 图像帧。

#### `src/control/`：自动控制逻辑

- `auto_control.py`：实现与 Tkinter、串口解耦的自动寻零状态机，根据视觉结果生成启动、调速或停止决策；
- `experiment_workflow.py`：识别整场实验进度，管理两项人工确认、设备初始化、自动搜索、中心稳定确认、结果记录和异常暂停。

#### `src/hardware/`：硬件通信

| 文件 | 作用 |
| --- | --- |
| `motor.py` | 实现 `R/r/S/D/+/-` 电机协议、JSON 状态解析、档位参数和内部自动调速。 |
| `micrometer.py` | 千分尺适配器占位文件，具体通信方式和数据格式尚未实现。 |
| `command_queue.py` | 在单个后台线程中顺序执行串口任务，并让停止命令具有更高优先级。 |
| `arduino.py` | 读取 Arduino 发送的激光测距等辅助数据。 |

#### `src/vision/`：图像识别与中心定位

| 文件 | 作用 |
| --- | --- |
| `detector.py` | 封装 Ultralytics YOLO，负责模型加载、设备选择、ROI 推理和异常输入保护。 |
| `class_names.py` | 根据模型的类别名称映射零级条纹和彩色条纹语义，不依赖固定类别 ID。 |
| `roi.py` | 使用亮度、阈值和形态学方法定位干涉条纹有效区域。 |
| `angle.py` | 使用频域特征估计条纹倾斜角度。 |
| `correct.py` | 管理画面旋转校正、手动角度偏置、缩放和平移。 |
| `fringe_center.py` | 在白光竖条纹区域内估计中心位置，并通过 `CenterTracker` 平滑结果、短时保持和拒绝异常跳变。 |

YOLO 检测框用于限定搜索范围，不直接把检测框中心当作最终中心条纹位置。

#### `src/ui/`：用户界面

- `app.py`：主界面控制器和唯一组装点，连接相机、视觉、电机、智能体与各插件；
- `theme.py`：统一颜色、字体和按钮样式；
- `markdown_renderer.py`：把助手输出中的 Markdown 和常见 LaTeX 表达渲染到 Tkinter 文本组件；
- `widgets/`：各功能面板，主界面通过组合这些面板构建网页式实验工作台。

`src/ui/widgets/` 中各插件的职责：

| 文件 | 界面功能 |

## 6. 配置说明

### 6.1 主配置 `config.yaml`

主要配置项包括：

- `camera`：相机索引、分辨率和帧率；
- `vision`：模型路径、置信度、IoU、输入尺寸和运行设备；
- `motor`：电机串口、波特率、超时和自动控制安全限制；
- `micrometer`：暂时只保留机构放缩系数，读数接口待硬件方案确定后补充；
- `experiment`：自动实验最大时间、中心稳定帧数、置信度和最大位置抖动；
- `arduino`：Arduino 串口参数；
- `agent`：DeepSeek 接口地址、模型、超时、输出长度和检索数量；
- `uncertainty`：置信水平等误差分析参数；
- `ui`：主题、语言和窗口大小。

如果配置使用 CUDA，但当前 PyTorch 无法使用 CUDA，YOLO 会记录警告并回退到 CPU。

### 6.2 DeepSeek 密钥

在本机文件 `config/secrets.yaml` 中填写：

```yaml
# 仅保存在本机，不会提交到 Git
deepseek_api_key: "你的 DeepSeek API Key"
```

也可以在启动程序前设置环境变量；环境变量优先级更高：

```powershell
$env:DEEPSEEK_API_KEY="你的 DeepSeek API Key"
python run.py
```

未配置密钥时，助手会使用本地知识检索结果进行降级回答。可以在实验助手面板中使用“测试 DeepSeek”检查连接状态。

### 6.3 标定配置

标定信息保存在 `config/calibration.yaml`。中心条纹模块首先输出像素坐标和像素偏移；需要换算为真实距离时，应使用与当前相机位置、分辨率和光路条件相匹配的标定数据。

### 6.4 电机串口协议

电机控制插件只提供手动控制。连接串口后，界面按照下表发送单字符命令：

| 命令 | 功能 |
| --- | --- |
| `R` | 正转启动 |
| `r` | 反转启动 |
| `S` | 停止 |
| `D` | 电机运行时切换方向 |
| `+` | 加速一个档位 |
| `-` | 减速一个档位 |
| 其他字符 | 请求电机返回 JSON 状态；程序默认发送 `?` |

固件的 10 档速度参数如下，档位数字越小，转速越高：

| 档位 | 脉冲频率（Hz） | 角速度（deg/s） | 每转耗时（s） |
| ---: | ---: | ---: | ---: |
| 1 | 5000 | 1125 | 0.32 |
| 2 | 4450 | 1001 | 0.36 |
| 3 | 3900 | 877 | 0.41 |
| 4 | 3350 | 754 | 0.48 |
| 5 | 2800 | 630 | 0.57 |
| 6 | 2250 | 506 | 0.71 |
| 7 | 1700 | 382 | 0.94 |
| 8 | 1150 | 259 | 1.39 |
| 9 | 800 | 180 | 2.00 |
| 10 | 500 | 112 | 3.20 |

自动实验使用同一套底层命令，但其搜索速度和安全限制由 `config.yaml` 中的 `motor.automatic` 管理，不在手动电机插件中显示。

## 7. 智能实验流程使用方法

人工必须完成的操作只有两项：

1. 使用红光调整仪器，使干涉条纹清晰且接近零光程差；
2. 放置白光光源。

完成后在“智能实验流程”面板依次勾选“仪器已用红光调整完成”和“白光光源已放置完成”，再打开“自动进行实验”。程序随后会自动检查相机、模型和电机，启动实时预测和中心检测，驱动电机寻找白光中心条纹，并在中心位置连续稳定后停车和保存记录。千分尺尚未接入，不会阻塞当前自动实验流程。

面板始终显示当前阶段、下一步和完成进度。关闭自动实验开关会立即结束自动搜索，但不会影响实验助手的普通问答功能。

以后接入千分尺后，配置中的 `scale_factor` 用于表示机构放缩系数：

```text
动镜实际位移 = (当前千分尺读数 - 参考读数) × scale_factor
```

如果仪器传动比为 `1/20`，可以设置 `scale_factor: 0.05`；应以实际机械结构或标定结果为准。

## 8. YOLO 模型要求

模型类别名称必须能够表达条纹语义。当前程序通过名称关键词进行兼容映射，例如：

- `zero_order`、包含 `zero` 或 `order` 的类别映射为零级条纹角色；
- `near_fringe`、`far_fringe`、包含 `color` 或 `fringe` 的类别映射为彩色条纹角色。

程序不会假设类别 ID 永远固定，因此更换模型时应检查模型的 `model.names`，不要只检查类别编号。

## 9. 测试与验证

运行全部无硬件测试：

```powershell
python -m unittest discover -s tests -v
```

真实设备联调建议依次进行：

1. 相机预览和分辨率测试；
2. 离线图片或视频的 YOLO 推理；
3. 中心条纹定位与偏移记录；
4. 电机空载串口测试；
5. 低速、小范围自动控制；
6. 完整实验流程验证。

## 10. 安全注意事项

- 首次联调应让电机空载，并使用低速、小范围运动；
- 自动控制前必须确认串口协议、运动方向和停止命令正确；
- 自动控制中的超时和条纹丢失停止不能替代机械限位；
- 模型、相机或电机插件关闭时，应同步停止预测和自动控制；
- 实验助手没有硬件控制权限，硬件动作由确定性程序和状态机处理；
- 关闭程序前应确认电机已经停止。

## 11. 开发约定

- 不要在 Tkinter 回调中直接执行模型推理、串口等待或在线请求；
- 新的自动控制逻辑优先放入 `src/control/`，并补充无硬件测试；
- YOLO 类别判断必须读取类别名称，不依赖固定类别 ID；
- 密钥、模型权重、原始 PDF、日志和临时数据不提交到 Git；
- 依赖版本统一维护在 `pyproject.toml`；
- 新增界面功能优先写成 `src/ui/widgets/` 下的独立插件；
- 可确定计算结果的误差和报告逻辑应逐步从大模型回答中拆出，放入 `src/uncertainty/` 和 `src/report/`。

更详细的线程边界和模块调用关系见 [`ARCHITECTURE.md`](ARCHITECTURE.md)。
